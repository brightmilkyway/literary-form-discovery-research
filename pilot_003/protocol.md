# Pilot 003 — 文学文本的序列响应实验（冻结协议）

## 1. 研究问题与边界

本实验把 James Joyce 的 *The Dead* 视为按原始顺序展开的文本序列：当计算系统
只获得截至位置 `t` 的文本时，预测、表示与解释响应如何变化；这些变化是否稳定、
可复现。本轮不恢复事件，不输入人物功能、主题、情节或文学转折标签，也不把模型
响应等同于人类读者的认知、情绪、惊讶或阅读难度。

本协议、检查点规则、主要距离与基线在读取 Pilot 003 轨迹结果前冻结。探索性峰值
只作为待解释坐标，不据此回调主要规则，也不能直接命名为文学结构。

## 2. 文本与检查点

- 来源：仓库根目录 `the_dead.txt`；运行记录文件 SHA-256。
- 规范化：UTF-8-sig 读取，换行统一为 `\n`，剥离开头独立标题 `THE DEAD`；
  正文的字符坐标均相对剥离标题后的字符串。
- 边界：空行定义自然段；词坐标只用于覆盖率与图的横轴，不改变段落边界。
- 检查点：固定 40 个，取 0 到末段的等距段落序号并四舍五入；首段与末段必选。
- 每个检查点保存段落序号、累计字符/词数、前缀 SHA-256 和距上次检查点的段数。
- prefix-only：检查点 `t` 的输入最多结束于该段末尾。实现测试逐点校验前缀哈希。

## 3. 表示响应（本轮实际主分析）

### 3.1 表示对象

为避免下载模型、长文本截断和由未来文本拟合 IDF，本轮使用无训练的固定特征哈希：

1. `char_hash`：小写字符 3–5 gram；
2. `word_hash`：小写词 1–2 gram。

两者均使用 32,768 维、非负哈希计数和 L2 归一化。哈希映射不从本文或未来正文
拟合，因此检查点表示不含后文统计量。哈希碰撞是明确的测量误差来源。

### 3.2 文本尺度

每种方法固定计算三个对象：当前检查点结束的最后 1 段（`p1`）、最后 4 段
（`p4`，开头不足时用已有段落）和全部累计前缀（`cumulative`）。局部尺度控制
长文本截断，但相邻检查点之间可能无重叠；累计尺度没有截断，却会因历史文本不断
累积而产生机械性平滑。三者不可互换解释。

### 3.3 主要指标与基线

- 主要轨迹：相邻检查点表示的余弦距离 `1 - cosine`；
- 离散程度：39 个相邻距离的均值、样本标准差和中位数；
- 简单基线一：每个相邻距离在该方法/尺度全部检查点两两距离中的经验百分位；
- 简单基线二：固定种子 `20261029`，随机置换 40 个检查点 500 次，比较相邻距离
  均值，报告上下尾及双侧经验 p。

置换基线只检验原始顺序是否比随机顺序更相似或更不相似；它不证明文学结构。
六个方法—尺度组合的 p 值属于诊断，本轮不将其作为确认性显著性结论。

## 4. 预测响应（获准执行后的追加冻结扩展）

在查看预测结果前追加并冻结：使用 `distilbert/distilgpt2` 因果语言模型及其
`GPT2TokenizerFast`，CPU 推理；逐 token 计算
`-log P(token_t | previous tokens)`。模型最长上下文为 1024 tokens，步幅固定 512；
每块预测后 512 tokens，并保留块内可用历史，所以除开头外目标 token 使用
512–1023 个历史 token。全文第一个 token 因无正文历史不计分。

每个 token 保存 ID、解码文本、正文字符区间、实际上下文长度及 nats/bits surprisal。
检查点摘要按 token 结束字符坐标分配到两个相邻检查点之间，报告均值、标准差、
中位数和 90 分位。模型仓库 revision、tokenizer、库版本及源文件哈希必须保存。
surprisal 仅是该模型在该上下文规则下的计算响应，不等同于人的惊讶或阅读难度。

## 5. 解释响应接口

`code/interpretive.py prepare` 为 40 个检查点生成 JSONL 请求。每一行保存完整原始
system/user 输入、前缀与提示词哈希、参数和模型字段。提示词要求 120–180 个英文词，
并固定输出三个 JSON 字符串字段：`current_understanding`、
`salient_uncertainties`、`evidence_basis`。参数固定为温度 0、最大 300 输出 token。

模型执行须经确认。外部执行后，响应 JSONL
必须逐检查点包含 `checkpoint_id`、精确 `model`、字符串 `output`，可含
`prompt_sha256`、`prefix_sha256` 与 `provider_metadata`；`validate` 会校验请求
哈希、完整性与 JSON schema，并把原始输入、输出和
运行元数据合并保存。之后可比较相邻输出，但不得强行映射到预设主题或事件类。

即使严格 prefix-only，模型也可能在预训练中接触过原作；提示约束不能消除这种
熟悉度。本接口测量的是模型在该输入协议下的生成响应，而不是无先验读者。

## 6. 稳健性、限制与停止规则

- 检查点按段落序号等距，词数间距不等；表中显式保存段落间距和词位置。
- `p1`/`p4` 的文本长度仍不等，距离可能反映篇幅、词汇和边界共同作用。
- 累计前缀的相邻距离会随总长度增加而机械下降，故只作尺度诊断。
- 哈希方法没有神经语义建模，方法间一致仅表示两种表面特征观察器的一致。
- 温度 0 不保证所有服务端完全确定；解释响应应在同一设置重复运行后再讨论稳定性。
- 解释响应以相同请求执行两轮，用同检查点输出距离评估温度 0 的实际重复性；
- 三个维度的事后对齐只报告预先已有指标的相关，不据相关结果筛选检查点；
- 首轮在 40 个检查点、六条表示轨迹、固定 500 次置换、两轮解释响应及一套
  surprisal 轨迹后停止；不因峰值位置或结果强弱增加筛选规则。

成功标准是可复现的数据链和清楚的测量边界，而不是发现“文学转折”。
